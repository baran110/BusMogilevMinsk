# Проверка авторизованного API

Подготовлена в локальной ветке `audit/handoff-2026-11-14`. [Авторизованный production-запуск 14 ноября](PRODUCTION_SMOKE_2026-11-14.md) завершил все 120 проверок расписания: вход работает, расписания возвращают 503, приёмка не пройдена. Инфраструктура описана в [сверке](HANDOFF_AUDIT_2026-11-14.md), ограничения источников — в [отдельном отчёте](SOURCE_CHECK_2026-11-14.md).

## План без сети

```powershell
pnpm smoke:api --plan
```

Запуск без аргументов также показывает только план. Дата вычисляется в Europe/Minsk. Для 14 ноября 2026 горизонт — 14 ноября–13 декабря включительно: два домена × два направления × 30 дат, 120 проверок расписания. Наличие переменной с ключом само по себе не запускает вход или сетевые запросы.

## Рабочий запуск после выбора ключа владельцем

В защищённых настройках среды задаётся `MM_SMOKE_ACCESS_KEY`: один выбранный существующий ключ. Не передавать его аргументом команды, не печатать значение, не копировать в Git, issues, PR или отчёты. Скрипт не читает архивы владельца, MM_Owner.txt, `.private-access`, cookies браузера или списки других ключей. `.env` автоматически не загружается.

После конкретного согласования проверки с выбранным ключом:

```powershell
pnpm smoke:api --run
```

Адреса фиксированы в коде: `https://bus-mogilev-minsk.pages.dev` и `https://mm-routes-mirror.vojtenkoa695.workers.dev`. Переопределение адресов и переходы по редиректам запрещены. Для каждого домена отдельно выполняются POST входа и DELETE выхода только своей диагностической сессии. Существующие ключи, SESSION_SECRET, рабочий KV, Cron и чужие сессии не изменяются. Самостоятельный вход владельца через браузер остаётся вариантом ручной приёмки; скрипт не извлекает такую сессию.

До передачи ключа проверяются 401 без сессии. После входа проверяются HttpOnly/Secure/SameSite=Lax, Path=/, срок cookie семь дней и отсутствие Domain. Проверка затем запрашивает 30 дат в обе стороны последовательно, с паузой 100 мс между запросами расписания. На нормальный полный запуск приходится 142 HTTP-запроса: 120 расписаний, 8 health и 14 проверок доступа/сессии. Каждый запрос имеет предел 20 секунд и ограничение JSON-ответа 3 MiB; повторов нет.

При неудачном входе или потере сессии запуск останавливается без подбора других ключей и без повторного входа. Редирект, ошибка сети, некорректный JSON или слишком большой ответ также останавливают проверку. При доступной сети finally пытается выйти; cookie не сохраняется на диск и не включается в отчёт. Выход проверяет удаление cookie клиента и 401 без него; это не отзыв подписанного токена на сервере. Сценарии отзыва и реального истечения проверяются существующими локальными тестами без изменения рабочих ключей.

HTTP 503 на расписании записывается как ошибка выбранной даты, а не «рейсов нет»; остальные даты продолжают проверяться при сохранённой сессии. Если во время выполнения наступит новая дата Минска, запуск останавливается: для нового горизонта нужен новый план.

## Отчёт и критерий приёмки

Локальный файл — `data/snapshots/api-smoke-report.json`, исключён из Git. В консоль выводится только краткий итог. Полные ответы API, рейсы, перевозчики, цены, ключи и cookies в отчёт не копируются. Ошибки fetch заменяются фиксированными кодами; текст ответа или исключения не печатается.

Каждая строка отчёта содержит домен, дату, направление, HTTP-статус и один из результатов:

- `ok`: схема и разрешённые ссылки корректны, поля/наблюдения согласованы, все подключённые импортёры подтвердили эту дату свежими данными.
- `degraded`: корректные данные, но stale/partial/backup либо неполное покрытие источников. Это не полная приёмка.
- `failed`: HTTP-ошибка, неверная схема, публичный кеш, просроченные цена/места, прошедший рейс, наблюдение старше семи дней, противоречивые длительность/выбранный продавец или неподтверждённая пустота.

Также сохраняются только счётчики: число рейсов, неизвестных цен, количеств мест и длительностей, максимальный возраст наблюдения, stale/partial/usedBackup. cachePolicy различает private-no-store, no-store и unsafe; наличие no-store без private тоже запрещает хранение и не считается ошибкой. По каждому импортёру из реестра указаны его фиксированный id, свежесть последней проверки конкретной даты/направления и возраст в минутах. Для ближних трёх дат предел — 15 минут, для дальних — 75 минут; цена и места проверяются по своим временам и пределу 15 минут. Время новой сборки не подменяет время наблюдения.

Подтверждённая пустота и неизвестные цена/места/длительность допустимы. Количество рейсов не обязано быть положительным. Для пустоты нужно актуальное подтверждение хотя бы одного подключённого источника; отсутствие подтверждений — failed, неполный набор источников — degraded.

`ready=true` и exit code 0 означают: все 120 строк имеют ok, все 14 проверок доступа успешны, все восемь health-проверок (общие ближняя/дальняя и БЖД ближняя/дальняя на каждом домене) здоровы. Любое отклонение даёт exit code 1. Даже ready=true не подтверждает полноту регулярных автобусов, доступ из Беларуси, доставку писем или право автоматически включить таймер.

## Локальная проверка реализации

```powershell
pnpm typecheck
pnpm test:run
pnpm build
```

Тесты используют фиктивный ключ, in-memory KV и реальные entrypoint-обработчики Pages/Worker. Внешние запросы заменены локальным транспортом. Проверены полная матрица 120 сочетаний, отдельный вход/выход на доменах, отказ до отправки ключа при открытом API, редиректы, потеря сессии, HTTP 503, повреждённые/слишком большие ответы и отсутствие ключей/cookies/деталей рейсов в отчёте. Отдельно проверены старые цена/места, семидневный предел, прошедшие отправления, неизвестные значения, неподтверждённая пустота и приватность кеша.

При подготовке прошли typecheck, все 108 unit/API-тестов и build. В их составе 20 новых smoke-сценариев; после добавления подробного возраста источников они повторно прошли отдельно вместе с typecheck. CLI --plan проверен без сети, CLI --run без ключа вернул exit code 1 и не создал отчёт. E2E интерфейса в этой итерации не перезапускались: интерфейс и его серверные обработчики не менялись. При подготовке рабочие ключи не использовались; последующий отдельно разрешённый production smoke-test описан выше. CI локальной ветки ещё не запускался.
