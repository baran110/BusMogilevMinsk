# Проверенные результаты и условия выпуска

Сведения относятся к диагностике 14–15 октября 2026 года и ветке восстановления. Production не менялся. Число рейсов зависит от времени и даты проверки и не является гарантией будущего предложения.

## Подтверждённая причина отказа

Старый GitHub workflow обновления выключен по неактивности (`disabled_inactivity`). Последний успешный сбор — 11 сентября 2026 года. Снимки имели срок жизни 48 часов, а `manifest:active` оставался без такого срока. Клиент при ошибках API подставлял демонстрационные рейсы.

[Диагностика KV, run 38622560070](https://github.com/baran110/BusMogilevMinsk/actions/runs/38622560070) подтвердила совпадение namespace с конфигурацией, наличие действительного старого manifest с `generatedAt=2026-09-11T17:56:49.167Z`, отсутствие обоих указанных снимков и отсутствие обоих устойчивых резервов. Это подтверждённый разрыв цепочки обновления и хранения, а не предположение по виду интерфейса.

В подготовленной версии ошибка показывается явно, сервер проверяет индивидуальный ключ, время наблюдения предложений сохраняется при переносе старых данных. Таймер подготовлен отдельно от нативного GitHub schedule, но ещё выключен.

### Полная проверка 15 октября

[Run 38774975899](https://github.com/baran110/BusMogilevMinsk/actions/runs/38774975899), коммит `cb4c3e1`: АвтоСлава — 473 исходные записи, Минск Экспресс — 175, ВитЭкспресс — 223, ГрандЭкспресс — 270, Новая Линия — 0. Все пять источников подтвердили 60 сочетаний даты/направления на горизонте 30 дней.

Atlas вернул 1324 записи и подтвердил 30 сочетаний из 60; весь 30-дневный горизонт этого источника не доказан. Для текущего дня обнаружен другой вариант выдачи: ни отправление, ни прибытие не содержат даты. Сохранённый календарь подтверждает выбранный день через `role="tab"`, `aria-selected="true"` и текст даты. Исправление принимает такие карточки только для фактического текущего дня, при совпадении выбранного календаря и длительности с часами поездки; URL сам по себе не является доказательством.

БЖД в этой и ближней проверках с GitHub runner не ответила за отведённое время (0 подтверждённых сочетаний). Отдельный обычный запрос из локальной среды 15 октября также завершился таймаутом чтения. Успешная проверка 14 октября не доказывает постоянную сетевую доступность 15 октября. Обхода ограничений, прокси или подмены региона не применялось. Нужны наблюдение доступности и разрешённый надёжный канал, если обычный HTML остаётся нестабильным.

После исправления подтверждения календаря [ближняя проверка 38776544625](https://github.com/baran110/BusMogilevMinsk/actions/runs/38776544625) на коммите `b38377f` подтвердила все шесть сочетаний у Atlas: 216 исходных записей, статус `ok`. БЖД в этом запуске по-прежнему вернула таймаут, а не подтверждение отсутствия поездов. Это завершённая проверка исправления текущей даты Atlas; дальний горизонт источника остаётся отдельным ограничением.

Общий результат этого полного запуска — 2433 будущие записи, снимки 1 283 507 и 1 270 202 байта. Оба меньше внутреннего лимита 2 MiB, но данные БЖД и неподтверждённых дат Atlas в них не входят. Это проверка фактического частичного набора, не гарантия размера после подключения всех перевозчиков. Расход CPU Cloudflare здесь не измеряется. Полный сбор не публиковал KV.

Дополнительно исправлен сбой, при котором отказ источника до разбора первой даты оставлял старую успешную отметку пустой выдачи. Теперь все запрошенные непроверенные даты получают ошибку, а старые предложения сохраняют прежний возраст. API отличает ошибку выбранной даты от сбоя другой даты.

## Регулярные автобусы: что ещё требуется

[Таблица автовокзала](https://avtovokzal-mogilev.by/raspisanie-megdugorodnih-marshrutov) содержит другие юридические лица и Автобусный парк №1. Это полезный перечень для проверки охвата, но не подтверждение продаж, мест и действия каждого рейса в выбранную дату. Не превращать общую недельную таблицу в актуальные предложения без проверки срока действия, отмен и направления.

[INFOBUS](https://partner.infobus.eu/) сообщает о возможности партнёрской API-интеграции. Бесплатность доступа, право использования в закрытом сервисе и охват внутренних белорусских рейсов пока не подтверждены. Аккаунт не создавался, заявки не отправлялись.

[Стандартные условия API Яндекс.Расписаний, п. 2.3.2](https://yandex.ru/legal/rasp_api/ru/) предусматривают бесплатный открытый доступ к пользовательскому проекту для неограниченного круга лиц. Нынешний сервис с десятью выдаваемыми ключами не соответствует этому условию. Не подключать API без отдельного разрешения поставщика и не менять требование владельца о закрытом доступе.

Для запроса разрешённого бесплатного источника владелец может использовать следующий текст:

> Я поддерживаю бесплатный закрытый сервис поиска транспорта Могилёв ↔ Минск для группы до десяти пассажиров. Продажи и приёма оплаты на нашем сайте нет: пользователь переходит к вашему продавцу. Нужны разрешённые данные о расписании обоих направлений на ближайшие 30 дней. Цены и места показываем только при их подтверждении; отсутствующие сведения обозначаем неизвестными. Подскажите, возможен ли бесплатный API или разрешённая выгрузка для такого использования, какие перевозчики охвачены и какие ограничения запросов действуют. Желаемая частота проверки ближайших трёх дат — десять минут, остальных — раз в час; готовы соблюдать ваши ограничения. Также нужны официальные ссылки поиска или бронирования с выбранной датой. Пожалуйста, укажите условия использования, срок действия расписаний и способ получения данных об отменах.

Пароли и API-ключи не отправлять в переписку проекта. После согласования способ подключения и необходимые защищённые настройки определяются по документации поставщика.

## Проверки и границы результата

[Quality 38776555133](https://github.com/baran110/BusMogilevMinsk/actions/runs/38776555133) на коммите `b38377f`: установка по lockfile, проверка типов, все 56 unit/API-тестов, сборка и 10 браузерных сценариев прошли. Локально проверка типов, 56 тестов, сборка и diff check также прошли. Последующие изменения этой документации не меняют проверенный код.

Локальная проверка зависимостей не обнаружила известных уязвимостей в установленном наборе. Это результат на дату проверки, а не бессрочная гарантия. Браузерные проверки прошли на GitHub runner; локально загрузить браузер не удалось.

До выпуска остаются обязательными:

1. Разобраться с сетевой доступностью БЖД, включая проверку с домашней и мобильной сети Беларуси. Повторные запросы не заменяют разрешённую интеграцию при устойчивом запрете.
2. Получить и проверить разрешённый источник регулярных автобусов; полный охват всех перевозчиков пока не доказан.
3. Дополнить проверку полного горизонта отсутствующими источниками и датами. CPU и квоты бесплатного Cloudflare окончательно измерить при разрешённом пробном запуске.
4. Настроить серверные секреты, проверить права токенов и отсутствие обходного автоматического деплоя Cloudflare Git integration.
5. Согласовать email владельца и включение бесплатного мониторинга.
6. Отдельно получить разрешение на production-деплой, публикацию KV и включение таймера; провести приёмку на домашней и мобильной сетях Беларуси.

Включение Cron, доставка писем, работа production-входа и доступ из Беларуси пока не проверены фактическим запуском. Инструкции выпуска и отката — [OPERATIONS.md](OPERATIONS.md).
