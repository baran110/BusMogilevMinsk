# Могилёв ↔ Минск

Существующее React/TypeScript-приложение для сравнения маршруток, автобусов и поездов с переходами к продавцам. Ветка восстановления исправляет получение, правдивость и защиту данных; дизайн и стек сохранены.

**Статус:** подготовка выпуска. Изменения в ветке и успешные тесты не означают, что production уже восстановлен. Деплой, запись расписаний, включение Cron и настройка уведомлений выполняются только после отдельного разрешения владельца.

## Как устроен сервис

GitHub Actions запускает адаптеры проверенных источников. Они возвращают нормализованные рейсы и результат проверки каждой даты/направления. Успешные и последние известные данные объединяются, проверяются и публикуются двумя снимками в KV. `manifest:active` выбирает текущую версию и хранит ссылки на предыдущую. Полные циклы также обновляют устойчивый резерв.

Pages Functions и Worker-зеркало используют общую серверную проверку индивидуального ключа и общий обработчик расписания. Клиент получает только выбранную дату. При ошибке он показывает недоступность и повтор запроса, а не демонстрационные рейсы.

Подготовленный отдельный Worker-таймер вызывает GitHub `workflow_dispatch`. Его Cron выключен до согласования. В новом collector нет нативного GitHub schedule, который раньше был отключён по неактивности.

## Правила выдачи

- Оба направления, календарь 30 дней, фильтры и сортировка; прошедшие отправления скрываются.
- Неизвестные цена, длительность и наличие мест не заменяются нулём, тремя часами или «места есть».
- Возраст наблюдения хранится отдельно у каждого продавца. Новая дата формирования снимка не обновляет старые предложения.
- Цена и места подтверждаются максимум 15 минут. Последнее известное расписание показывается до семи дней с явной отметкой возраста.
- Успешный пустой ответ отличается от ошибки, блокировки, неверной даты и изменившейся схемы.
- Цена и места карточки относятся к выбранному продавцу. Дедупликация сохраняет варианты бронирования и не объединяет два разных рейса одного источника только по совпадению времени.
- Бронирование ведёт только на разрешённый HTTPS-домен соответствующего источника. Сайт не принимает оплату.
- До десяти личных ключей проверяются сервером; HttpOnly/Secure-сессии на семь дней, отзыв отдельного ключа, отсутствие публичного кеша защищённого API.

## Источники и ограничения

Единый реестр — `data/sources.json`. `enabled` и параметры адаптера управляют сбором. Записи `link-only` — справочные ссылки, без импорта рейсов и без утверждения о доступности расписания. Файл `data/carriers.json` — архивный перечень кандидатов, а не доказательство текущего охвата.

Проверка 14 октября 2026 года: пять HTTP-адаптеров успешно ответили для обоих направлений и трёх ближайших дат. АвтоСлава, Минск Экспресс, ВитЭкспресс и ГрандЭкспресс вернули предложения; Новая Линия — корректную пустую выдачу. После фильтрации и точных дублей получено 190 будущих записей. Это локальная диагностика без публикации KV, а не обещание количества предложений завтра.

Atlas требует отдельной проверки переключения дат и указания перевозчика; его нельзя автоматически считать юридическим перевозчиком. Выдача БЖД требует подтверждения текущего формата и даты. TicketBus не имеет работающего импортера в этой версии, а пробный обычный HTTP-доступ вернул отказ. Не обходить CAPTCHA, авторизацию, robots/технические запреты или ограничения частоты. При ограничении нужны официальная интеграция или разрешённая выгрузка.

Все регулярные автобусы и поезда пока нельзя считать покрытыми. Состояние источников фиксируется по реальным диагностическим результатам, а не по доступности их главных страниц.

## Проверки кода

Node.js 22+, pnpm 11.7.0 согласно `packageManager`:

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test:run
pnpm build
pnpm exec playwright install --with-deps chromium
pnpm test:e2e
```

Браузерные тесты сами запускают явно выделенный Vite API с тестовым KV и реальными серверными обработчиками. Тестовые данные находятся в `tests/fixtures`, не входят в клиентскую сборку и не публикуются в Cloudflare. Проверяются серверный вход, выход, истечение сессии, оба направления, мобильные фильтры, неизвестные значения и отказ API без вымышленных рейсов. Отдельные API-тесты вызывают оба hosting entrypoint.

`pnpm dev` не подставляет демо при отсутствующем API. Для изолированной ручной проверки тестового стенда можно явно запустить `E2E_FIXTURES=1 pnpm dev`; это только dev-сервер с тестовыми перевозчиками и тестовым ключом из `tests/fixtures/schedule.ts`.

## Проверки внешних источников

Обычные тесты не собирают реальные расписания. Проверка сети зависит от доступности и правил поставщика:

```bash
SOURCE_IDS=avtoslava,minsk-express,vitexpress,grandexpress,new-line pnpm collect:sample --near
```

Результат записывается только в игнорируемый `data/snapshots/diagnostic.json`. Выбор `SOURCE_IDS` запрещён для производственной публикации, чтобы диагностическая выборка случайно не заменила весь набор. Не запускайте `pnpm collect` без разрешения на запись рабочего KV.

Read-only KV-диагностика: `pnpm diagnose:kv` в защищённой среде с секретами или workflow **Диагностика KV без публикации**. Она не выводит токены, цены, личные данные или ключи пассажиров.

## Рабочие workflows

| Workflow | Назначение |
|---|---|
| `quality.yml` | Проверки типов, unit/API, сборка и e2e для PR. Без Cloudflare-секретов. |
| `diagnose.yml` | Чтение manifest/снимков/резервов, без записи. |
| `diagnose-sources.yml` | Ограниченная проверка БЖД/Atlas без секретов и публикации. |
| `collect.yml` | Ручной или внешний dispatch на `main`, подтверждение `publish`, режим `near/full`. |
| `deploy.yml` | Ручное подтверждение `production`, затем проверки того же коммита и публикация проверенной сборки. |

После разрешённого запуска: ближний сбор каждые десять минут, полный примерно раз в час; публичный `/api/health` для бесплатного внешнего мониторинга. Настройка секретов, квоты, email, приёмка в Беларуси и безопасный откат описаны в инструкции владельцу.
